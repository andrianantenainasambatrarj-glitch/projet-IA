    Comment ça marche

    Une seule chose à faire : déposer la capture d'écran de votre graphique (et, si vous le souhaitez, vos cours en PDF). Il n'y a ni symbole, ni période, ni unité de temps à choisir : tout est lu sur l'image.

    1. 1. Lecture de la capture — l'image est transcrite : actif, unité de temps, tendance, figures, niveaux, bougies notables.
    2. 2. Données du même actif, dans la même unité de temps — une capture en 5 minutes est analysée sur des bougies de 5 minutes ; l'actif lu sur l'image fait référence (si vous aviez indiqué un autre symbole dans une ancienne version, c'est l'image qui gagne, et c'est écrit dans le résultat).
    3. 3. Ingestion de vos cours — vos PDF/notes sont découpés par sections, vectorisés (embeddings) et stockés dans la base locale.
    4. 4. Analyse technique — le moteur calcule tendance, structure, supports/résistances, figures chartistes et chandeliers, RSI, MACD, ADX, ATR, Bollinger, volumes, puis un score directionnel et un plan (entrée, stop, objectifs, R/R).
    5. 5. Méthode du cours — les extraits les plus pertinents de vos cours sont récupérés (recherche hybride vecteurs + BM25) et le modèle rédige en citant [Source n], en tenant compte du rythme de la capture (scalping en M5, swing en H4/D1…).
    6. 6. Résultat — lecture de la capture, méthode appliquée, prédiction probabiliste, plan de trading, scénario alternatif, limites et avertissement.

    Quel modèle Gemini est utilisé ?

    Google renomme et retire régulièrement ses modèles (par exemple gemini-2.5-flash, retiré aux nouveaux comptes et remplacé par gemini-3.6-flash). {{ app_name }} détecte automatiquement les modèles disponibles pour votre clé et bascule sur le suivant si l'un d'eux n'existe plus : vous n'avez rien à modifier. Le modèle réellement utilisé est indiqué dans l'en-tête et sur /api/health (llm.modele_vision). Pour l'imposer : VISION_MODEL=gemini-3.6-flash.

    Où sont mes données ?

    Vos PDF importés, l'index vectoriel, l'historique des analyses et les notes restent sur votre hébergement (SQLite local, dossier data/). Aucune donnée n'est envoyée à un tiers, sauf l'image et le texte soumis au fournisseur LLM que vous avez choisi (uniquement si une clé API est configurée).

    Protection par jeton (API_ACCESS_TOKEN)

    Si la variable est définie, les appels /api/* exigent l'en-tête X-API-Token. Cette interface fonctionne (le jeton lui est transmis automatiquement), mais il s'agit d'une protection légère : toute personne ayant accès à la page peut lire le jeton dans le code source. Pour un usage strictement privé, rendez le service privé ou ajoutez une authentification complète.

    Limites assumées

    • Aucune garantie de gain : les sorties sont des scénarios probabilistes.
    • La lecture d'image peut se tromper sur les valeurs d'échelle ou d'unité de temps.
    • Les données de marché sont gratuites (Binance pour la crypto, Yahoo/Stooq pour le reste) avec un léger différé ; si aucune source ne répond, une série de démonstration clairement signalée est utilisée.
    • Les embeddings par défaut (hachage local) sont légers : utilisez un fournisseur d'embeddings API pour une recherche sémantique plus fine.
