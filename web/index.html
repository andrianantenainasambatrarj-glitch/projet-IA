Comment configurer Telegram (gratuit, 3 minutes)

  1. Ouvrez Telegram, cherchez @BotFather et envoyez /newbot. Choisissez un nom, puis copiez le jeton fourni (forme 123456:ABC-DEF…).
  2. Cherchez votre nouveau bot et envoyez-lui /start (obligatoire : un bot ne peut pas écrire le premier).
  3. Récupérez votre chat id : ouvrez https://api.telegram.org/bot<JETON>/getUpdates dans un navigateur et lisez result[0].message.chat.id.
  4. Sur votre hébergement, ajoutez les variables TELEGRAM_BOT_TOKEN et TELEGRAM_CHAT_ID (et NOTIFY_ENABLED=true pour la veille), puis redémarrez.

Alternative sans Telegram : NOTIFY_WEBHOOK_URL (Discord : Paramètres du salon → Intégrations → Webhooks → copier l'URL ; ntfy : https://ntfy.sh/votre-sujet).

Comment ça marche

  1. Ingestion — vos PDF/notes sont découpés par sections, puis vectorisés (embeddings) et stockés dans la base locale.
  2. Analyse technique — le moteur calcule tendance, structure, supports/résistances, figures chartistes et chandeliers, RSI, MACD, ADX, ATR, Bollinger, volumes, puis un score directionnel et un plan (entrée, stop, objectifs, R/R).
  3. Recherche RAG — la description du graphique et la question servent de requête ; les 3-5 extraits les plus pertinents de vos cours sont récupérés (recherche hybride vecteurs + BM25).
  4. LLM vision — si une clé API est configurée, l'image est transcrite en description structurée, puis le modèle rédige l'analyse finale en s'appuyant explicitement sur vos cours (citations [Source n]).
  5. Réponse — conclusion, prédiction probabiliste, plan de trading, scénario alternatif, limites, avertissement.

Activer la vision et la rédaction par IA

Ajoutez une variable d'environnement sur votre hébergement puis redémarrez : GEMINI_API_KEY (clé gratuite sur Google AI Studio — recommandé), OPENAI_API_KEY, ANTHROPIC_API_KEY ou OPENROUTER_API_KEY. Options utiles : LLM_PROVIDER (forçage du fournisseur), VISION_MODEL, TEXT_MODEL, EMBEDDING_PROVIDER (gemini pour des embeddings sémantiques de meilleure qualité).

Quel modèle Gemini est utilisé ?

Google renomme et retire régulièrement ses modèles (par exemple gemini-2.5-flash, retiré aux nouveaux comptes et remplacé par gemini-3.6-flash). TradeVision IA détecte automatiquement les modèles disponibles pour votre clé et bascule sur le suivant si l'un d'eux n'existe plus : vous n'avez rien à changer. Le modèle réellement utilisé est indiqué dans /api/health (llm.modele_vision) et après chaque analyse. Pour l'imposer manuellement, définissez VISION_MODEL (ex. gemini-3.6-flash).

Limites assumées

  • Aucune garantie de gain : les sorties sont des scénarios probabilistes.
  • La lecture d'image peut se tromper sur les valeurs d'échelle ou de temps.
  • Les données de marché sont gratuites (Yahoo/Stooq) avec un léger différé ; si le réseau est indisponible, l'application bascule sur des séries de démonstration clairement signalées.
  • Les embeddings par défaut (hachage local) sont légers : pour une recherche sémantique plus fine, utilisez un fournisseur d'embeddings API ou sentence-transformers.
  • Si API_ACCESS_TOKEN est défini, les appels /api/* exigent l'en-tête X-API-Token. Cette interface fonctionne (le jeton lui est transmis automatiquement), mais il s'agit d'une protection légère : toute personne ayant accès à la page peut lire le jeton dans le code source. Pour un usage strictement privé, rendez le service privé ou gérez une authentification complète.
